# Vela v7.1 — hicoco session hardening (draft)

> Status: **draft**. Phase A landed, Phase B/C pending.
> Release-target commit: TBD
> Baseline: v7.0.7 (`7296b8c`)

## Why

Four real pipelines run on the hicoco project against v7.0.7 surfaced 11
quality regressions and ~1000 sub-agent tool_use (executor avg 57.7,
verifier 55.2). Every regression maps to a v7.1 module.

## Phase A — the 4 independent modules

These four ship together because their call graphs don't overlap and
each one carries its own test + reverse-check evidence.

### M1 — commit/branch not-a-git-repo guard
**Before**: hicoco's 4 pipelines all completed `commit` with
`status: "skipped"` because the project had no `.git/`. The user only
realised their work was never persisted when reading the final report.
**After**: `cmdInit`, `cmdBranch`, and `cmdCommit` now detect the
non-git case, emit a multi-line `⛔ BLOCKED` banner to stderr with the
exact recovery steps, and return `status: "blocked"` in the JSON.
`init` additionally embeds a `pipelineWarnings` array and a top-level
`git: { repo, branch, dirty }` snapshot so the PM surfaces the problem
at step 1 instead of step 13.
**Files**: `scripts/cli/vela-engine.js` (cmdInit/cmdBranch/cmdCommit)
**Test**: `scripts/tests/test-commit-not-a-repo.sh` — 18 assertions,
including a git-sandbox reverse-sanity check to prove the banner fires
only in the non-git case.
**Reverse check**: Reverting the engine makes 13/18 assertions fail.

### M5 — slug fs-safe truncation
**Before**: `slugify()` used `.substring(0, 30)` (JS char count).
Korean input produced `별도-downloa`, `대상-사이`, `baseurl` — half-word
artifact directories that also broke shell quoting in downstream
grep/find commands. No side-car for the full request, so truncated
pipelines lost the original prompt.
**After**: new `slugifyEx()` caps at **64 UTF-8 bytes** (not chars),
walks the cut back to the nearest `-` boundary, appends `-trunc` when
truncation triggered, and budgets the suffix in up-front so
post-truncation length is provably ≤ 64. `cmdInit` additionally
drops `request.txt` with the full original prompt when the slug was
truncated, so humans and agents can always recover the intent.
**Files**: `scripts/cli/vela-engine.js` (slugify + slugifyEx + cmdInit)
**Test**: `scripts/tests/test-slug-truncate.sh` — 15 assertions
including 4 unit cases (short/long-ko/long-mix/200-char) and an
end-to-end cmdInit integration check.
**Reverse check**: Reverting makes 10/15 assertions fail. Pre-v7.1
output confirmed byte length 70 and mid-syllable cut `-url-구`,
matching the exact hicoco bug.

### M8 — advance command (record + transition one-shot)
**Before**: hicoco PM emitted 146 top-level Bash calls, the largest
single pattern being `record pass` followed by `transition` on every
successful step. After transition the PM often called `state` to
figure out which agent to spawn next — three CLI calls per happy step.
**After**: new `advance [pass|fail|reject]` command. `advance pass`
records the verdict + advances atomically, writes `pipeline-state.json`
once, and returns `{previousStep, currentStep, nextStep, revision,
circuitOpen, nextAction}`. `nextAction` is a one-line hint like
`"spawn vela-executor then vela-reviewer"` so the PM can skip the
extra `state` call. `record` and `transition` are fully preserved for
back-compat.
**Files**: `scripts/cli/vela-engine.js` (cmdAdvance + applyVerdict
helper + nextActionHint lookup table)
**Test**: `scripts/tests/test-engine-advance.sh` — 18 assertions
covering pass/fail/reject/default/invalid verdicts + legacy
record/transition preservation.
**Reverse check**: Reverting makes 14/18 assertions fail (the 4 that
still pass are Phase 5/6 — legacy `record`/`transition` / unknown
command branch — which v7.0.7 already supported).

### M12 — CLAUDE.md cd-rule injection on upgrade
**Before**: v7.0.7 added the "Bash tool — never use bare `cd`" section
to `install()`'s CLAUDE.md template, but only for first-time
initialisation. Pre-v7.0.7 projects like hicoco have a CLAUDE.md that
`upgrade()` deliberately skips (to preserve user customisation), so
they never get the rule and keep stepping on the subshell-cd footgun
on every session.
**After**: `upgrade()` reads the existing CLAUDE.md, checks for the
marker `Bash tool — never use bare \`cd\``, and appends the section
if absent. Idempotent — re-running `upgrade` after the first injection
is a no-op. Files with the marker already present are untouched
(size unchanged).
**Files**: `scripts/install.js` (upgrade)
**Test**: `scripts/tests/test-claudemd-cd-rule-injection.sh` — 10
assertions across 3 scenarios: no CLAUDE.md at all, existing without
marker, existing with marker.
**Reverse check**: Reverting makes 6/10 assertions fail.

## CI wiring

All 4 Phase A tests added to `.github/workflows/test.yml` with step
ids `s_cng`, `s_slug`, `s_adv`, `s_cmd`, report rows, env vars, and
`continue-on-error: true` matching the existing convention. The
`s_meta` step already auto-enforces every test file be referenced.
